# 採用 月次KPI管理シート

Instagram・TikTok・X・YouTube・YouTubeショートの数字を1枚で追い、
LINE友だち・エントリー・採用までつなげるシート。
月次レビューとレポートスライドまで自動で作る。

| 用途 | ファイル |
|---|---|
| KPIシート本体（数式・目安・色分け・メニュー） | `gas/InstaKpiSheet.gs` |
| 月次レビュー（総評をClaudeに書かせる） | `gas/InstaKpiReview.gs` |
| 月次レポートのスライド（PPTX書き出し） | `gas/InstaKpiDeck.gs` |
| 空のシートをCSVから作る（旧・単一チャネル版） | `tools/build_insta_kpi_csv.py` |
| Excel版（旧・単一チャネル版） | `tools/build_insta_kpi_sheet.py` |

## 行の持ち方

1行1レコードを「月 × チャネル」にしてある。月ごとにチャネル行が並び、
最後に合計行が入る。チャネルを増やすときは `CHANNELS` に足して
「シートを整える」を実行するだけ。列は増えない。

```
8月  Instagram          …
8月  TikTok             …
8月  X                  …
8月  YouTube            …
8月  YouTubeショート     …
8月  Facebook           …
8月  Meta広告            …  ← 広告費を入れる
8月  TikTokプロモート     …  ← 広告費を入れる
8月  合計               ← チャネル行の SUM。レビューとスライドはここを見る
9月  Instagram          …
```

合計行の位置は `summaryRow_(monthIndex)` で決まる。
レビューもスライドもこの関数を通すので、チャネルを増減しても追従する。

## 列

| 区分 | 内容 |
|---|---|
| 入力（チャネルごと） | 投稿数／広告費／フォロワー数／表示回数／リーチ数／保存＋シェア／プロフィール表示／リンククリック／LINE友だち追加／エントリー数／面接／採用数／3ヶ月定着数 |
| 入力（月ぜんぶ） | LINE友だち総数（月末）。合計行にだけ入れる |
| 自動 | リーチ率／保存シェア率／プロフ表示率／リンククリック率／LINE登録率／エントリー率／面接率／採用率／定着率／表示→採用率／1採用あたり投稿数／採用単価／LINE登録単価 |
| 目安 | 3行 | 主要4指標の 悪い／普通／良い |
| 集計 | 年間合計／月平均（合計行だけを SUMIF で拾う） |

## 指標の役割

追いかける数字を3種類に分けている。

| 種類 | 例 | 役割 |
|---|---|---|
| ストック（資産） | フォロワー数、LINE友だち総数 | 増えないと毎月ゼロから表示を取りに行くことになる |
| 先行指標 | 保存＋シェア（保存シェア率） | 増えた翌月に表示回数が伸びる。唯一「先が読める」数字 |
| 結果 | 表示回数〜採用数 | 起きたあとの数字 |

さらに「質」として定着率を置く。採用数だけを追うと、辞める人を採り続けても
数字上は成功に見えてしまう。3ヶ月定着数は3ヶ月遅れて分かるので、
採用した月の行へさかのぼって入れる（直近の月が空欄なのは正常）。

ストック指標は年間合計で足さない。`stock: true` を付けた列は、
年間合計行に「最後に入っている値」を出す。

## 列は名前で引く

列文字を直書きしていない。`INPUT_COLUMNS` / `MONTH_COLUMNS` / `CALC_COLUMNS` の
定義から `KPI_COL`（指標名 → 列文字）を組み立て、`col_('採用数')` で引く。
数式も `'=IFERROR({採用数}{r}/{面接}{r},"")'` のように指標名で書き、
書き込み時に `resolveFormula_` が列文字へ差し替える。

列を足しても並べ替えても、参照している側（レビュー・スライド）を直さなくてよい。
入力値の退避も指標名で行うので、列が動いても正しい列に戻る。

「表示回数」はインプレッション・再生回数をまとめた呼び方。媒体で名前が違うだけで
中身は同じ。リーチが取れない媒体は空欄でよく、その場合は率も出ない。

## 目安と色分け

赤＝悪い、緑＝普通、黄色＝良い。対象は プロフ表示率・リンククリック率・
LINE登録率・表示→採用率 の4列。

| 指標 | 悪い | 普通 | 良い |
|---|---|---|---|
| プロフ表示率 | 〜3% | 3〜5% | 5%〜 |
| リンククリック率 | 〜5% | 5〜10% | 10%〜 |
| LINE登録率 | 〜20% | 20〜40% | 40%〜 |
| 表示→採用率 | 〜0.005% | 0.005〜0.02% | 0.02%〜 |
| 定着率 | 〜70% | 70〜90% | 90%〜 |

**もとはInstagramの一般値**。TikTokやYouTubeは母数の数え方が違うので水準もずれる。
実績が3〜6ヶ月たまったら、`BENCHMARKS` をチャネルの実態に合わせて書き換える。

空欄が赤くならないよう、条件付き書式は `ISNUMBER()` で必ず絞っている。

## 使い方

1. CSVをGoogleドライブにアップロードしてスプレッドシートとして開く
2. 拡張機能 → Apps Script に `gas/InstaKpiSheet.gs` を貼り付けて保存
3. 関数 `setupKpiSheet` を実行（初回のみ承認）
4. 月ごとのチャネル行に、C〜K列の実数を入力する。合計行と率は自動

`setupKpiSheet` は入力済みデータを「月＋チャネル」で突き合わせて引き継ぐ。
Instagramだけだった旧レイアウトも読めて、その場合はInstagram行へ移す。

## 構成

| 区分 | 列・行 | 内容 |
|---|---|---|
| 入力 | B〜K | 投稿数／インプレッション／リーチ数／プロフアクセス数／リンクタップ数／LINE登録／面接／採用数(LINE経由)／その他問い合わせ／採用数(その他経由) |
| 自動 | L〜W | 採用数合計、1投稿あたりインプ、リーチ率、プロフアクセス率、リンクタップ率、LINE登録率、面接率、採用率、LINE→採用率、その他採用率、リーチ→採用率、1採用あたり投稿数 |
| 目安 | 3行 | 主要4指標の 悪い／普通／良い のライン |
| 集計 | 17・18行 | 合計（率は通期で割り直し）／平均 |

率は `IFERROR` でくるんであるので、未入力の月は空欄のまま。

## 目安と色分け

赤＝悪い、緑＝普通、黄色＝良い。対象は次の4列。

| 指標 | 悪い | 普通 | 良い | 根拠 |
|---|---|---|---|---|
| プロフアクセス率 | 〜3% | 3〜5% | 5%〜 | Instagram運用の一般的な目標値 |
| リンクタップ率 | 〜5% | 5〜10% | 10%〜 | 10%が分岐点とされる |
| LINE登録率 | 〜20% | 20〜40% | 40%〜 | LINE友だち追加のCVR一般値（50%超も出る） |
| リーチ→採用率 | 〜0.005% | 0.005〜0.02% | 0.02%〜 | 公開ベンチマークなし。上の3つ＋面接率・採用率からの逆算 |

ラインは `gas/InstaKpiSheet.gs` の `BENCHMARKS` と
`tools/build_insta_kpi_sheet.py` の `BENCHMARKS` に定義してある。
自社の実績が溜まったらこの2箇所を書き換える。

空欄が赤くならないよう、条件付き書式は `ISNUMBER()` で必ず絞っている。

## 再生成

```bash
python3 tools/build_insta_kpi_csv.py -o "docs/Instagram採用KPI管理シート.csv"

pip install openpyxl
python3 tools/build_insta_kpi_sheet.py -o "docs/Instagram採用KPI管理シート.xlsx"
```

CSV版は率を `TEXT(x,"0.0%")` で文字列に整形しているため、書式設定なしでパーセント表示になる。
GAS版とExcel版は数値のまま持ち、表示形式でパーセント表示にしている（色分けにはこちらが必要）。

## 月次レビュー

`gas/InstaKpiReview.gs` を同じApps Scriptプロジェクトに置くと、
「月次レビュー」シートに 総評／良かった点／ボトルネック／改善アクション を
Claude が書けるようになる。

事前に「プロジェクトの設定」→「スクリプト プロパティ」で登録する。

| プロパティ | 必須 | 中身 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 必須 | AnthropicのAPIキー |
| `ANTHROPIC_WORKSPACE_ID` | 条件付き | `wrkspc_` で始まるワークスペースID |

個人に紐づいたキー（identity-linked）を使う場合、`anthropic-workspace-id`
ヘッダーが無いと400になる。その場合だけ `ANTHROPIC_WORKSPACE_ID` を足す。
ワークスペース単位で発行したキーなら不要。

| メニュー | 動き |
|---|---|
| 月次レビューシートを作る | 13ヶ月分の行とKPIシート参照の数値サマリーを用意する。書き込み済みの本文とリンクは引き継ぐ |
| この月の総評をAIに書かせる | 選択中の行の月について、C〜F列を書く。もう一度実行すると上書き |

Claudeに渡すのは、その月と前月の数値、目安、そして
`judge_()` で先に判定した 悪い／普通／良い のラベル。
判定をコード側で確定させてから渡すことで、
モデルが目安を読み違えて別の水準だと言い出すことがなくなる。

応答は `【総評】` などの見出しで4つに切り分けて各列に入れる
（`parseSections_`）。見出しが取れなかった場合は全文を総評列に入れて取りこぼさない。

モデルは `claude-opus-5`、`thinking: adaptive`、`effort: low`。
effort を上げると深く書くが時間もかかり、Apps Script の通信が打ち切られやすくなる。
`output_config.effort` の1箇所で変えられる。

アカウントによっては `thinking` や `output_config` が通らず400になるため、
400が返ったら一度だけそれらを外して再送する（`callClaudeForReview_`）。
拒否時の自動フォールバック（`fallbacks`）はベータで、使えないアカウントで
400になるため入れていない。

APIのエラーは `claudeErrorMessage_` で日本語に変換する。
キー間違い(401)・残高不足・レート制限(429)は、何をすればいいかまで出す。
全文は Apps Script の実行ログにも残る。

## 月次レポートのスライド

`gas/InstaKpiDeck.gs` を同じプロジェクトに置くと、その月の数値と総評から
7枚のスライドを組み立て、PPTXに書き出してDriveに保存する。

| メニュー | 動き |
|---|---|
| この月のレポートを作る（総評＋スライド） | 総評を書かせてから、続けてスライドまで作る |
| この月のスライドだけ作り直す | 総評はそのままに、スライドだけ作り直す |

保存先はマイドライブの「Instagram採用レポート」フォルダ。
Googleスライド（編集用）と .pptx（配布用）の両方が入る。

生成すると、月次レビューシートのH・I列にその月のレポートへの
リンクを書き込む（`writeDeckLinks_`）。シートから直接開ける。
シートを作り直しても、リンクは数式のまま引き継がれる。

### 体裁

SINISの月次レポートに合わせてある。同じ相手に並べて出しても揃って見えるようにした。

| | |
|---|---|
| ページ | A4横 842×595pt |
| 書体 | Noto Sans JP（`FONT` で切替。PowerPoint側で完全に揃えるなら `游ゴシック`） |
| 主色 | ネイビー `#3e63a3` |
| 文字 | `#303030` / 補足 `#595959` / 薄い `#8c8c8c` |
| 面 | 白 `#ffffff` / 薄面 `#f8f8f8` |
| 増減 | 増 `#1f79f2`（青） 減 `#e33721`（赤） |

上部にセクションナビ（現在地を濃く）、その下に細い区切り線、
下部にCOMMENT枠、右下にページ番号。参考レポートの構造をなぞっている。

### 構成

1. 表紙 … 英語の小見出し＋日本語の大見出し、下に対象月と作成日の帯
2. 全体サマリー … 数値カード5枚（採用数のみネイビーで強調）＋COMMENTに総評
3. ファネル … 各段の転換率をバーで＋COMMENTにボトルネック
4. 目安に対する評価 … 4指標のメーター。目盛りは「良い」の2倍を上限にとり、
   悪い／普通の境目に線を立てる
5. 良かった点とボトルネック
6. 来月やること
7. 指標の見方 … 各指標の意味と目安の根拠

### 設計上の約束

- 判定は色だけで表さない。必ず「悪い／普通／良い」の文字と凡例を添える。
  赤と緑は色覚特性によっては見分けにくく、検証でも
  CVD分離が基準を下回るため、ラベルの併記が前提になっている
- ファネルの面接・採用の段は業種差が大きいため目安を置かず、ネイビーにする
- 実数に比例した漏斗形は描かない。リーチ3万に対して採用数人では
  下段が潰れて読めないため、各段の転換率をバーにする
- 位置はページサイズから計算する。A4での作成に失敗して既定サイズに
  なっても崩れない（両方のサイズで枠外・重なりが無いことを確認済み）

### PPTXへの書き出し

`SlidesApp` にはページサイズを指定する手段が無いため、A4横のプレゼンは
Slides API を直接叩いて作り、`SlidesApp.openById` で開き直している
（`createDeck_`）。失敗したら既定サイズで作る。

組み上げたあと Drive API の export で PPTX に変換する（`exportAsPptx_`）。
Drive と Slides の権限が要るので、初回だけ承認をやり直すことになる。

図形を1つずつ置くため、生成には2〜3分かかる。

## 判定ラインをシートから変える

「悪い／普通／良い」の線は業種で変わる。コードを触らずに変えられるよう、
スクリプトの `BENCHMARKS` は**初期値だけ**を持ち、実際に効く数字は
シートの入力セルに置いた。

| 行 | 中身 |
| --- | --- |
| 2行目 | 業種プルダウン（選ぶと下の2行が入れ替わる） |
| 3行目 | 見出し |
| 4行目 | これ未満なら赤（`BAD_ROW`） |
| 5行目 | これ以上なら黄色（`GOOD_ROW`） |

- 条件付き書式は固定値ではなく `$S$4` `$S$5` のようなセル参照を見る。
  シートで数字を直すと、その場で色分けが変わる（再実行が要らない）
- 判定ラインが空欄・文字のときに全部が赤くならないよう、
  ルールの条件に `ISNUMBER` を3つ並べている（値・赤ライン・黄ライン）
- 入力欄には 0〜1 の数値検証を付けている。`3` とだけ打つと弾かれ、
  `3%` か `0.03` なら通る。％表示のセルへの誤入力を防ぐため
- 総評（`judge_` / `benchmarkText_`）とスライド（`benchmarkFor_` / `glossary_`）は
  `activeBenchmarks_()` 経由でシートの値を読む。1回の実行につき1度だけ読んで使い回す
- 逆に入れられた（黄 ≤ 赤）ときは黄を赤の2倍に直して使う。色分けが破綻しないように
- 業種プルダウンは単純トリガー `onEdit` で反応する。承認が要らない代わりに、
  失敗しても入力の邪魔をしないよう例外は握り潰している。
  メニューの「業種の目安を入れ直す」でも同じことができる
- 作り直しの前に `readBenchmarkSettings_` で読み、あとで書き戻す。
  手で直した基準がリセットされないため

`INDUSTRY_PRESETS` の数字は出発点であって正解ではない。実績が3〜6ヶ月たまったら
「月平均を4行目、その1.3〜1.5倍を5行目」に置き換えると自社基準になる。

## 広告タブ

CPC・CPM・フリークエンシーは広告の中でしか意味を持たず、オーガニックの
ファネルとは物差しが違う。同じ表に混ぜると列が増えるだけで読めなくなるため、
`広告` タブに分けた（`gas/InstaKpiAds.gs`）。

- 入力は広告タブだけ。月次KPIの Meta広告 / TikTokプロモート 行は
  `adPullFormula_()` が作る `='広告'!C7` のような数式で引く。二重入力にならない
- そのため月次KPI側では、広告チャネル行に退避した値を書き戻さない
  （数式を上書きしてしまうため、`writeMonthBlocks_` で数式を優先する）
- 広告タブは月次KPIより**先に**作る。あとから作ると参照が `#REF!` のまま固まる
- 目標の採用単価・LINE登録単価を入れると、超えた月が赤、収まった月が緑になる
- 行数はチャネル定義に従うので、`AD_ROWS_PER_MONTH` などを定数ではなく関数にした。
  Apps Script はファイルを順に評価するため、定数のままだと読み込み順で
  `PAID_CHANNELS is not defined` になる（`AD_COL` も同じ理由で遅延生成にした）

## 運用スコアとランク（S / A / B / C）

合計行に「運用スコア（0〜100点）」と「ランク」を出す。
**4・5行目の目安に対する絶対評価**で、自社の他の月とは比べない。

最初は月どうしの相対評価（`PERCENTRANK`）で作ったが、実務では使えなかった。
半年ぶんたまるまで判定できず、運用を始めた月に物差しが無い。
市場（目安）基準に切り替えたことで初月から出るようになり、
業種プルダウンを変えると物差しごと変わるという分かりやすさも得た。

### 点数に入るのは、運用でコントロールできる5指標だけ

| 指標 | 悪い | 良い | 点数 |
| --- | --- | --- | --- |
| リーチ率 | 〜60% | 85%〜 | ○ |
| 保存シェア率 | 〜0.5% | 2%〜 | ○ |
| プロフ表示率 | 〜3% | 5%〜 | ○ |
| リンククリック率 | 〜5% | 10%〜 | ○ |
| LINE登録率 | 〜15% | 25%〜 | ○ |
| エントリー率 | 〜10% | 25%〜 | — |
| 採用率 | 〜20% | 40%〜 | — |
| 定着率 | 〜70% | 90%〜 | — |
| 表示→採用率 | 〜0.001% | 0.005%〜 | — |
| 1採用あたり投稿数（逆） | 60本〜 | 〜25本 | — |
| 達成率 | 〜80% | 100%〜 | — |

エントリー率から先は求人内容・時給・現場の対応で決まる部分が大きい。
色は付けて原因を探せるようにしつつ、運用の点数には入れない（`noScore`）。
達成率も、目標を自分で決められる以上は点数に入れない。

表示→採用率と1採用あたり投稿数は、月の採用が0人か1人かで跳ねる。
母数が小さすぎるので月次の評価には使わず、年間合計・月平均の行で見る。

- 指標ごとに 良い＝2点／普通＝1点／悪い＝0点。満点を100点に直す
- **数字が入っている指標だけで平均する**。追っていない項目は分母にも入らない
- 切れ目は2行目の「評価：〜」で切り替え（`RANK_MOODS`）。
  甘め S75/A50/B25、ふつう S85/A60/B35、厳しめ S90/A70/B50。**既定は甘め**
- 先月よりスコアが上がった月と、比べる先月が無い月にはCを付けない
- 出す／出さないの判定は行そのものを見る（`rankRowGuard_`）

### 少ないほど良い指標

1採用あたり投稿数は判定の向きが逆になる。`invert: true` を付けると、
条件付き書式・スコア・`judge_`・目安ラベルがすべて向きを反転する。

- 4・5行目の見出しから「未満／以上」を外した。列によって向きが変わるため。
  どちら向きかは各セルのメモに入れている
- 入力検証も指標によって変える。％の指標は0〜1、本数の指標（`count: true`）は0〜100000

`BENCHMARKS` は `CALC_COLUMNS` より**前**に置くこと。
`CALC_COLUMNS` の初期化時に `rankScoreFormula_()` が呼ばれるため、
後ろにあると `undefined.forEach` で落ちる。

## CVポイント（LINE友だち追加）の目標と達成率

このシートのコンバージョンはLINE友だち追加。合計行に「LINE追加 目標」を入れると
達成率が出て、他の率と同じ仕組みで色が付く。

- 目標は `MONTH_COLUMNS`（合計行だけに入れる列）に置いた。チャネル行では意味を持たないため
- 達成率は `BENCHMARKS` に `{bad: 0.80, good: 1.00}` で登録した。
  100%で達成・80%未満は未達というKPI運用の一般的な区切り。
  4・5行目の入力欄から変えられる点は他の指標と同じ
- 業種プリセット（`INDUSTRY_PRESETS`）には達成率を入れていない。
  達成率は業種で変わる数字ではないので、業種を切り替えても上書きされない
- **達成率はランクのスコアに入れていない。** 目標を自分で決められる指標を
  相対評価に混ぜると、目標を低く置くだけでランクが上がってしまう

### 目標の逆算ブロック

年平均行の下に置いた（`writeGoalBlock_`）。採用したい人数を入れると、
**自社の月平均**のエントリー率・面接率・採用率で割り戻して必要な友だち追加数を出す。
他社の平均ではなく自分の実績で割るので、初月から使える数字になる。

広告だけで集めた場合の金額も出す。LINE友だち追加広告（CPF）の相場が
1件100〜150円なので、中央値130円で掛けている。

入力した「月に採用したい人数」は、作り直しの前に `readGoalInput_` が
**A列のラベル文字を探して**読む。行番号ではなくラベルで探すのは、
チャネルや月を増やすとブロックの位置が動くため。

## 0で埋まって読めなくなるのを防ぐ

使っていないチャネルの行が `0` `¥0` で埋まると、動いている数字が読めない。
かといって値を消すと合計が壊れるので、**値は0のまま、見た目だけ消す**。

- `hideZero_(format)` が書式の3区画目（ゼロのときの表示）を空にする。
  `#,##0` → `#,##0;-#,##0;`
- 消すのは**入力欄と金額だけ**。率の0.0%は消さない。
  率は分母が0なら数式が空を返すので、`0.0%` と出ている時点で
  「やったが取れなかった」という意味を持つ。ここを消すと本当に悪い月が見えなくなる
- 広告タブから引く数式も `=IF(参照="","",参照)` にした。
  空欄をそのまま引くと0になり、入れていない月に0が並ぶ

### 月平均は、数字を入れていない月を混ぜない

`AVERAGEIF(B範囲,"合計",範囲)` は合計行を全部平均するので、
まだ埋めていない月（SUMが0）まで頭数に入り、平均が実態より下がっていた。
`AVERAGEIFS(範囲, B範囲,"合計", 表示回数範囲,">0")` に変え、
**数字が入っている月だけ**を平均するようにした。
目標の逆算ブロックはこの月平均を使うので、ここがずれると必要数もずれる。

### 動いていない行は色を付けない

条件付き書式の条件に、その行の表示回数が0より大きいことを足した。
やっていないチャネルの `0.0%` を赤く塗ると、本当に悪い数字が埋もれる。

## 「まだ記入していない」を0%にしない

`=IFERROR(A/B,"")` は、Aが空でBに数字があると **0%** を返す。
3ヶ月定着数のように後から埋まる欄では、これが「全員辞めた」と同じ表示になり、
定着率が赤くなって暫定ランクまで下がっていた。

定着率と保存シェア率は `=IF(分子="","",IFERROR(分子/分母,""))` にして、
分子が空のあいだは率も空にする。
