# 採用 月次KPI管理シート

Instagram・TikTok・X・YouTube・YouTubeショートの数字を1枚で追い、
LINE友だち・エントリー・採用までつなげるシート。
月次レビューとレポートスライドまで自動で作る。

| 用途 | ファイル |
|---|---|
| KPIシート本体（数式・目安・色分け・メニュー） | `gas/InstaKpiSheet.gs` |
| 月次レビュー（総評をClaudeに書かせる） | `gas/InstaKpiReview.gs` |
| 月次レポートのスライド（PPTX書き出し） | `gas/InstaKpiDeck.gs` |
| 空のシートをCSVから作る（旧・単一チャネル版） | `tools/build_insta_kpi_csv.py` |
| Excel版（旧・単一チャネル版） | `tools/build_insta_kpi_sheet.py` |

## 行の持ち方

1行1レコードを「月 × チャネル」にしてある。月ごとにチャネル行が並び、
最後に合計行が入る。チャネルを増やすときは `CHANNELS` に足して
「シートを整える」を実行するだけ。列は増えない。

```
8月  Instagram        …
8月  TikTok           …
8月  X                …
8月  YouTube          …
8月  YouTubeショート   …
8月  その他            …
8月  合計             ← チャネル行の SUM。レビューとスライドはここを見る
9月  Instagram        …
```

合計行の位置は `summaryRow_(monthIndex)` で決まる（`FIRST_ROW + 月 × 7 + 6`）。
レビューもスライドもこの関数を通すので、チャネルを増減しても追従する。

## 列

| 区分 | 列 | 内容 |
|---|---|---|
| 入力（チャネルごと） | C〜K | 投稿数／表示回数／リーチ数／プロフィール表示／リンククリック／LINE友だち追加／エントリー数／面接／採用数 |
| 入力（月ぜんぶ） | L | LINE友だち総数（月末）。合計行にだけ入れる |
| 自動 | M〜U | リーチ率／プロフ表示率／リンククリック率／LINE登録率／エントリー率／面接率／採用率／表示→採用率／1採用あたり投稿数 |
| 目安 | 3行 | 主要4指標の 悪い／普通／良い |
| 集計 | 96・97行 | 年間合計／月平均（合計行だけを SUMIF で拾う） |

「表示回数」はインプレッション・再生回数をまとめた呼び方。媒体で名前が違うだけで
中身は同じ。リーチが取れない媒体は空欄でよく、その場合は率も出ない。

## 目安と色分け

赤＝悪い、緑＝普通、黄色＝良い。対象は プロフ表示率・リンククリック率・
LINE登録率・表示→採用率 の4列。

| 指標 | 悪い | 普通 | 良い |
|---|---|---|---|
| プロフ表示率 | 〜3% | 3〜5% | 5%〜 |
| リンククリック率 | 〜5% | 5〜10% | 10%〜 |
| LINE登録率 | 〜20% | 20〜40% | 40%〜 |
| 表示→採用率 | 〜0.005% | 0.005〜0.02% | 0.02%〜 |

**もとはInstagramの一般値**。TikTokやYouTubeは母数の数え方が違うので水準もずれる。
実績が3〜6ヶ月たまったら、`BENCHMARKS` をチャネルの実態に合わせて書き換える。

空欄が赤くならないよう、条件付き書式は `ISNUMBER()` で必ず絞っている。

## 使い方

1. CSVをGoogleドライブにアップロードしてスプレッドシートとして開く
2. 拡張機能 → Apps Script に `gas/InstaKpiSheet.gs` を貼り付けて保存
3. 関数 `setupKpiSheet` を実行（初回のみ承認）
4. 月ごとのチャネル行に、C〜K列の実数を入力する。合計行と率は自動

`setupKpiSheet` は入力済みデータを「月＋チャネル」で突き合わせて引き継ぐ。
Instagramだけだった旧レイアウトも読めて、その場合はInstagram行へ移す。

## 構成

| 区分 | 列・行 | 内容 |
|---|---|---|
| 入力 | B〜K | 投稿数／インプレッション／リーチ数／プロフアクセス数／リンクタップ数／LINE登録／面接／採用数(LINE経由)／その他問い合わせ／採用数(その他経由) |
| 自動 | L〜W | 採用数合計、1投稿あたりインプ、リーチ率、プロフアクセス率、リンクタップ率、LINE登録率、面接率、採用率、LINE→採用率、その他採用率、リーチ→採用率、1採用あたり投稿数 |
| 目安 | 3行 | 主要4指標の 悪い／普通／良い のライン |
| 集計 | 17・18行 | 合計（率は通期で割り直し）／平均 |

率は `IFERROR` でくるんであるので、未入力の月は空欄のまま。

## 目安と色分け

赤＝悪い、緑＝普通、黄色＝良い。対象は次の4列。

| 指標 | 悪い | 普通 | 良い | 根拠 |
|---|---|---|---|---|
| プロフアクセス率 | 〜3% | 3〜5% | 5%〜 | Instagram運用の一般的な目標値 |
| リンクタップ率 | 〜5% | 5〜10% | 10%〜 | 10%が分岐点とされる |
| LINE登録率 | 〜20% | 20〜40% | 40%〜 | LINE友だち追加のCVR一般値（50%超も出る） |
| リーチ→採用率 | 〜0.005% | 0.005〜0.02% | 0.02%〜 | 公開ベンチマークなし。上の3つ＋面接率・採用率からの逆算 |

ラインは `gas/InstaKpiSheet.gs` の `BENCHMARKS` と
`tools/build_insta_kpi_sheet.py` の `BENCHMARKS` に定義してある。
自社の実績が溜まったらこの2箇所を書き換える。

空欄が赤くならないよう、条件付き書式は `ISNUMBER()` で必ず絞っている。

## 再生成

```bash
python3 tools/build_insta_kpi_csv.py -o "docs/Instagram採用KPI管理シート.csv"

pip install openpyxl
python3 tools/build_insta_kpi_sheet.py -o "docs/Instagram採用KPI管理シート.xlsx"
```

CSV版は率を `TEXT(x,"0.0%")` で文字列に整形しているため、書式設定なしでパーセント表示になる。
GAS版とExcel版は数値のまま持ち、表示形式でパーセント表示にしている（色分けにはこちらが必要）。

## 月次レビュー

`gas/InstaKpiReview.gs` を同じApps Scriptプロジェクトに置くと、
「月次レビュー」シートに 総評／良かった点／ボトルネック／改善アクション を
Claude が書けるようになる。

事前に「プロジェクトの設定」→「スクリプト プロパティ」で登録する。

| プロパティ | 必須 | 中身 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 必須 | AnthropicのAPIキー |
| `ANTHROPIC_WORKSPACE_ID` | 条件付き | `wrkspc_` で始まるワークスペースID |

個人に紐づいたキー（identity-linked）を使う場合、`anthropic-workspace-id`
ヘッダーが無いと400になる。その場合だけ `ANTHROPIC_WORKSPACE_ID` を足す。
ワークスペース単位で発行したキーなら不要。

| メニュー | 動き |
|---|---|
| 月次レビューシートを作る | 13ヶ月分の行とKPIシート参照の数値サマリーを用意する。書き込み済みの本文とリンクは引き継ぐ |
| この月の総評をAIに書かせる | 選択中の行の月について、C〜F列を書く。もう一度実行すると上書き |

Claudeに渡すのは、その月と前月の数値、目安、そして
`judge_()` で先に判定した 悪い／普通／良い のラベル。
判定をコード側で確定させてから渡すことで、
モデルが目安を読み違えて別の水準だと言い出すことがなくなる。

応答は `【総評】` などの見出しで4つに切り分けて各列に入れる
（`parseSections_`）。見出しが取れなかった場合は全文を総評列に入れて取りこぼさない。

モデルは `claude-opus-5`、`thinking: adaptive`、`effort: low`。
effort を上げると深く書くが時間もかかり、Apps Script の通信が打ち切られやすくなる。
`output_config.effort` の1箇所で変えられる。

アカウントによっては `thinking` や `output_config` が通らず400になるため、
400が返ったら一度だけそれらを外して再送する（`callClaudeForReview_`）。
拒否時の自動フォールバック（`fallbacks`）はベータで、使えないアカウントで
400になるため入れていない。

APIのエラーは `claudeErrorMessage_` で日本語に変換する。
キー間違い(401)・残高不足・レート制限(429)は、何をすればいいかまで出す。
全文は Apps Script の実行ログにも残る。

## 月次レポートのスライド

`gas/InstaKpiDeck.gs` を同じプロジェクトに置くと、その月の数値と総評から
7枚のスライドを組み立て、PPTXに書き出してDriveに保存する。

| メニュー | 動き |
|---|---|
| この月のレポートを作る（総評＋スライド） | 総評を書かせてから、続けてスライドまで作る |
| この月のスライドだけ作り直す | 総評はそのままに、スライドだけ作り直す |

保存先はマイドライブの「Instagram採用レポート」フォルダ。
Googleスライド（編集用）と .pptx（配布用）の両方が入る。

生成すると、月次レビューシートのH・I列にその月のレポートへの
リンクを書き込む（`writeDeckLinks_`）。シートから直接開ける。
シートを作り直しても、リンクは数式のまま引き継がれる。

### 体裁

SINISの月次レポートに合わせてある。同じ相手に並べて出しても揃って見えるようにした。

| | |
|---|---|
| ページ | A4横 842×595pt |
| 書体 | Noto Sans JP（`FONT` で切替。PowerPoint側で完全に揃えるなら `游ゴシック`） |
| 主色 | ネイビー `#3e63a3` |
| 文字 | `#303030` / 補足 `#595959` / 薄い `#8c8c8c` |
| 面 | 白 `#ffffff` / 薄面 `#f8f8f8` |
| 増減 | 増 `#1f79f2`（青） 減 `#e33721`（赤） |

上部にセクションナビ（現在地を濃く）、その下に細い区切り線、
下部にCOMMENT枠、右下にページ番号。参考レポートの構造をなぞっている。

### 構成

1. 表紙 … 英語の小見出し＋日本語の大見出し、下に対象月と作成日の帯
2. 全体サマリー … 数値カード5枚（採用数のみネイビーで強調）＋COMMENTに総評
3. ファネル … 各段の転換率をバーで＋COMMENTにボトルネック
4. 目安に対する評価 … 4指標のメーター。目盛りは「良い」の2倍を上限にとり、
   悪い／普通の境目に線を立てる
5. 良かった点とボトルネック
6. 来月やること
7. 指標の見方 … 各指標の意味と目安の根拠

### 設計上の約束

- 判定は色だけで表さない。必ず「悪い／普通／良い」の文字と凡例を添える。
  赤と緑は色覚特性によっては見分けにくく、検証でも
  CVD分離が基準を下回るため、ラベルの併記が前提になっている
- ファネルの面接・採用の段は業種差が大きいため目安を置かず、ネイビーにする
- 実数に比例した漏斗形は描かない。リーチ3万に対して採用数人では
  下段が潰れて読めないため、各段の転換率をバーにする
- 位置はページサイズから計算する。A4での作成に失敗して既定サイズに
  なっても崩れない（両方のサイズで枠外・重なりが無いことを確認済み）

### PPTXへの書き出し

`SlidesApp` にはページサイズを指定する手段が無いため、A4横のプレゼンは
Slides API を直接叩いて作り、`SlidesApp.openById` で開き直している
（`createDeck_`）。失敗したら既定サイズで作る。

組み上げたあと Drive API の export で PPTX に変換する（`exportAsPptx_`）。
Drive と Slides の権限が要るので、初回だけ承認をやり直すことになる。

図形を1つずつ置くため、生成には2〜3分かかる。
