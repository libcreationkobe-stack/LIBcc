# 導入手順・全体設計

## 全体フロー

```
            ┌─────────────────────────── スプレッドシート「投稿管理」───────────────────────────┐
            │ A種別  B ソース  C ファイル参照     D メモ   E 文字起こし  F 投稿文  G ステータス  H 更新日時 │
            └──────────────────────────────────────────────────────────────────────────────┘
  動画: Dropbox/Drive ──(Zapier)──▶ Notta文字起こし ──(Zapier)──▶ E列 または Driveの.txt
                                        │  メニュー［GBP自動化］→［下書きを作成］
                                        ▼
   ┌──────────────┐   動画   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │ 文字起こしを   │ ───────▶ │ Claudeで要約  │──▶│ F列に投稿文   │──▶│ G列=確認待ち  │
   │ 受け取る       │          │ (claude-opus) │   │              │   │              │
   └──────────────┘          └──────────────┘   └──────────────┘   └──────────────┘
   ┌──────────────┐   写真
   │ Drive/Dropbox │ ───────▶ メモからClaudeで投稿文 ＋ 写真は「投稿準備済」フォルダへ
   │ から取得       │
   └──────────────┘
                                        ▼
                          人が F列の投稿文と写真を確認 → GBPへ投稿 → G列=投稿済
```

## 1. スプレッドシートの準備

「投稿管理」という名前のシートを作り、1行目に見出しを入れます（列の意味は `Config.gs` の `COL` と対応）。

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| 種別 | ソース | ファイル参照 | メモ | 文字起こし | 投稿文 | ステータス | 更新日時 |

- **種別**: `動画`（リール）または `写真`
- **ソース**: `drive` または `dropbox`
- **ファイル参照**:
  - 写真(drive) … 共有URL または ファイルID
  - 写真(dropbox) … パス（例: `/photos/2026-06-09.jpg`）
  - 動画 … Notta×Zapierで文字起こしを **E列に直接** 入れる場合は空でOK。
    Driveの `.txt` で受け取る場合はその共有URL/IDを指定（`.vtt` / `.srt` も可）
- **メモ**: 写真パターンの元情報、または動画パターンの補足
- **文字起こし(E列)**: Notta×Zapierがここに書き込む or 自動取得した結果が入ります
- **投稿文 / 更新日時**: 自動入力されます
- **ステータス**: 空 or `未処理` の行が処理対象。完了で `確認待ち` になります

## 2. コードの配置

### 方法A: clasp（推奨）
```bash
npm i -g @google/clasp
clasp login
clasp create --type sheets --title "GBP自動化" --rootDir ./gas
clasp push
```

### 方法B: 手動
Apps Script エディタを開き、`gas/` 内の各 `.gs` をファイルごとに貼り付け、`appsscript.json` の内容をマニフェストに反映します。

## 3. APIキーの登録（スクリプトプロパティ）

Apps Scriptエディタ →「プロジェクトの設定」→「スクリプト プロパティ」に追加：

| キー | 用途 |
|------|------|
| `ANTHROPIC_API_KEY` | Claude（投稿文生成）。https://console.anthropic.com で取得 |
| `DROPBOX_TOKEN` | Dropbox を使う場合のみ |

> 文字起こしは Notta(+Zapier) 側で行うため、Notta用のAPIキーはGASには登録しません。

## 4. 実行

スプレッドシートを再読み込みすると **［GBP自動化］** メニューが出ます。
- **［下書きを作成（未処理の行）］** … 未処理行を一括処理
- **［選択中の行だけ処理］** … テスト時に便利

## 5. Notta × Zapier の連携設定（文字起こし）

Notta はコードから直接叩ける公開APIが無いため、**Zapier 経由（Nottaビジネスプラン以上）** で文字起こしを自動化します。Zapで以下のような流れを組みます。

1. **トリガー**: Dropbox（または Google Drive）の指定フォルダに新規ファイル
2. **アクション(Notta)**: そのファイルを Notta にインポートして文字起こし
3. **アクション(出力)**: 文字起こしテキストを下記いずれかへ
   - **Google Sheets**: 「投稿管理」シートに行を追加し、A列=`動画`、E列=文字起こし、G列=`未処理` をセット ← 全自動でおすすめ
   - **Google Drive**: `.txt` で保存し、その行の C列 にファイルを指定

参考: [Notta×Zapier](https://www.notta.ai/integrations/zapier) / [文字起こしをDriveへ自動保存](https://support.notta.ai/hc/ja/articles/28674681591323-Zapier%E3%82%92%E4%BD%BF%E3%81%84%E6%96%87%E5%AD%97%E8%B5%B7%E3%81%93%E3%81%97%E3%83%87%E3%83%BC%E3%82%BF%E3%82%92%E8%87%AA%E5%8B%95%E7%9A%84%E3%81%ABGoogle-Drive%E3%81%AB%E4%BF%9D%E5%AD%98%E3%81%99%E3%82%8B)

> 手動運用も可能です。Nottaで文字起こし→テキストをコピーして E列 に貼り付けるだけでも、以降の Claude 投稿文生成は動きます。

## 6. 自動化（任意）

毎朝など定期実行したい場合は、Apps Script の「トリガー」で `processPendingRows` を時間主導で設定します。
（Zapierでシートに行が追加されるたびに走らせたい場合も、この時間主導トリガーで拾えます。）

---

## 設計上の注意・ステップアップ

- **文字起こしはClaudeではできません。また Notta も直接APIで呼べません。** そのため Notta(+Zapier) が作った文字起こしを GAS が受け取る方式です（`Transcribe.gs`）。Notta側で音声・動画の長さ／プランの上限に注意してください。
- **GBPへの自動投稿まで進める場合**: Google の Business Profile API（旧 Google My Business API）の利用申請・審査が必要です。承認後は「最新情報（localPosts）」と「写真（media）」をAPI投稿でき、`F列=確認待ち` の行を自動投稿する処理に拡張できます。
- **写真の扱い**: 現状は「投稿準備済」フォルダに集約するところまで。API投稿に進む際はここから media アップロードにつなげます。
- **コスト**: Claude と 文字起こしは従量課金です。まず数件でテストしてから一括処理してください。

# 請求書の自動作成

「請求書」シートに1行入力して実行すると、Googleドキュメントの請求書とPDFを自動生成します。
請求番号・消費税・合計・支払期限は自動計算です。

## 準備（最初の1回だけ）

1. メニュー **［請求書］→［シートを準備］** … 「請求書」シートを見出し付きで作成
2. メニュー **［請求書］→［テンプレートを作成］** … Driveの「請求書」フォルダにテンプレートを作成し、IDを自動登録
3. 作られたテンプレートを開き、**自社名・住所・登録番号・振込先**を記入（`{{ }}` は消さないこと）
   - `gas/Config.gs` の `INVOICE.COMPANY` に書いておけば、毎回自動で差し込まれます
   - テンプレートに直接書いてもOKです（その場合 `COMPANY` は空のままで構いません）

## シートの列

| 列 | 内容 | 備考 |
|----|------|------|
| A | 請求番号 | 空なら自動採番（例: `INV-202609-001`） |
| B | 請求日 | 空なら実行日 |
| C | 請求先 | 必須 |
| D | 敬称 | 空なら「御中」 |
| E | 件名 | 例: `6月分 制作費` |
| F | 支払期限 | 空なら翌月末 |
| G | 明細 | **1行1明細**（セル内改行は `Alt + Enter`） |
| H | 備考 | |
| I | 合計金額 | 自動入力 |
| J | ステータス | 自動入力（`作成済` / `エラー`） |
| K | ドキュメント | 自動入力 |
| L | PDF | 自動入力 |
| M | 更新日時 | 自動入力 |

### 明細（G列）の書き方

```
リール動画制作,3,30000      ← 品目, 数量, 単価
撮影ディレクション,50000     ← 品目, 単価（数量は1）
```

- 区切りは **カンマ / 読点 / タブ**、1行が1明細です
- 桁区切りのカンマは **使わない**でください（`30000` と入力）
  - どうしても使う場合は `¥30,000` `30,000円` のように**単位を付ける**と正しく読み取れます
  - 単位の無い `撮影費,10,000` は「数量10 / 単価000」とも読めるため、**推測せずエラー**にします
- 数量・単価が0の行はエラーになります（金額の入力漏れを防ぐため）

## 実行

- **［請求書］→［請求書を作成（未処理の行）］** … ステータスが空の行をまとめて処理
- **［請求書］→［選択中の行だけ作成］** … テスト時に便利

生成物は Drive の **「請求書」フォルダ**に `INV-202609-001_株式会社サンプル` の名前で保存されます。
エラーになった行は J列（ステータス）にメモとして原因が入ります。

## 設定（`gas/Config.gs` の `INVOICE`）

| 項目 | 既定値 | 内容 |
|------|--------|------|
| `TAX_RATE` | `0.10` | 消費税率 |
| `TAX_ROUNDING` | `floor` | 端数処理（`floor` / `round` / `ceil`） |
| `NUMBER_PREFIX` | `INV-` | 請求番号の接頭辞 |
| `MAKE_PDF` | `true` | PDFも書き出すか |
| `COMPANY` | 空 | 自社名・住所・TEL・登録番号・振込先 |

> 💡 **インボイス制度**の登録番号は `COMPANY.REG_NO` かテンプレートに記入してください。

# 台本の自動作成

「台本」シートにテーマとメモを入れて実行すると、Claudeが構成を考え、
**毎回同じフォーマットのGoogleドキュメント**を自動生成します。

## 準備

メニュー **［台本］→［シートを準備］** で「台本」シートを作成します。

## シートの列

| 列 | 内容 | 備考 |
|----|------|------|
| A | 企画・テーマ | 必須 |
| B | メモ・話したい素材 | あるほど台本の精度が上がります |
| C | 尺（秒） | 空なら45秒 |
| D | 媒体 | 空なら「リール」 |
| E | ステータス | 自動入力 |
| F | ドキュメント | 自動入力 |
| G | 更新日時 | 自動入力 |

## 生成されるドキュメントの構成

1. タイトル案（3案）
2. 冒頭フック（0〜2秒）
3. **構成表**（秒数 / 映像・カット / セリフ / テロップ）
4. 締め・CTA
5. ハッシュタグ
6. 撮影メモ
7. 元メモ（入力した内容をそのまま記録）

生成物は Drive の **「台本」フォルダ**に `2026-09-13_テーマ名` の名前で保存されます。

## 実行

- **［台本］→［台本を作成（未処理の行）］**
- **［台本］→［選択中の行だけ作成］**

> 💡 フォーマットを変えたい場合は `gas/Scenario.gs` の `buildScenarioDoc_()`（見た目）と
> `gas/Claude.gs` の `generateScenario()`（AIへの指示）を編集します。

# テスト

金額計算まわりは Node.js でテストできます。

```
node tests/run.js
```

明細のパース・消費税の端数処理・請求番号の採番・支払期限の計算を検証します。
`gas/Invoice.gs` を編集したら実行してください。
