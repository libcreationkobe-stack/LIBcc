# LIB経営管理シート（PL）に足す経営判断タブ

`gas/PlDashboard.gs` を「LIB経営管理」のApps Scriptに貼り、
`setupManagementSheets` を実行すると5つのタブができる。

既存のPL入力表には一切書き込まない。ラベルを頼りに値を引くので、
行を挿入しても月の列を足しても壊れない。

| タブ | 役割 |
|---|---|
| 設定 | 税率・目標・決算月・預金残高など。ここだけ触れば全部の計算が変わる |
| ダッシュボード | 今月の実績、確保すべき額、使っていい金額、危険信号 |
| 資金繰り予測 | 12ヶ月の残高推移。現金が尽きる月を先に見つける |
| 納税カレンダー | 決算月から逆算した、いつ何を払うか |
| 支払い予定 | 項目ごとの支払日を入れると、月内の支払いが日付順に並ぶ |
| 月内の資金繰り | 日ごとの残高。月末が黒字でも途中で尽きる月を見つける |

## 前提

法人（株式会社）／決算11月／消費税は来季から課税事業者。
いずれも設定タブの値で、変えれば別の条件でも使える。

## PL表の読み取り方

行はB列のラベル、列は1行目の「◯月」でMATCHして引く。

```
INDEX(PL!$A:$BZ, MATCH(売上ラベル, PL!$B:$B, 0), MATCH(対象月, PL!$1:$1, 0))
```

ラベル名は設定タブで変えられる（`rowSales` / `rowPaid`）。
シート名も空なら「支払い合計」がある表を自動で探す。

## 税額の計算

`corporateTaxFormula_` が年間所得から次を合算する。税率はすべて設定タブの値。

- 法人税 … 800万円以下は軽減税率、超過分は本則
- 地方法人税 … 法人税額 × 率
- 住民税 … 法人税割（法人税額 × 率）＋ 均等割（赤字でもかかる）
- 事業税 … 400万円／800万円で3段階
- 特別法人事業税 … 事業税額 × 率

年間所得は「累計利益 ÷ 実績月数 × 12」で見込む。月が進むほど精度が上がる。
月々の積立は年間見込み ÷ 12。

消費税は簡易課税・第5種（みなし仕入率50%）を想定し、
売上に対する積立率4.5%を既定にしている（税込売上 × 10/110 × 50%）。
区分が違えば設定タブの率を変える。

**すべて資金繰りのための概算であって、申告額そのものではない。**
実際の申告・納付額は顧問税理士に確認する前提で作ってある。

## 資金繰り予測の組み方

- 事業年度の12ヶ月を決算月から並べる（決算11月なら12月始まり）
- 残高は「残高の基準日」の月から積み上げる。それより前の月は空欄
- 基準月は月初残高として扱い、その月の収支も足す（月が飛ばない）
- 納税は決算月+2ヶ月に確定分、+8ヶ月に中間分を置く
- 判定は 残高マイナス→危険 / 安全ライン未満→注意 / それ以外→良好

安全ラインは「実績月の平均支払額 × 安全月数」。

## 年間グラフ

資金繰り予測の表の下に3つ並べる。1年分をまとめて見るためのもの。

| グラフ | 形 | なぜその形か |
|---|---|---|
| 売上と支払 | 縦棒・2系列 | 月ごとの量を並べて比べるため |
| 月末残高の推移 | 折れ線・2系列 | 水準の推移を追うため。ゼロを割った瞬間が読める |
| 利益率の推移 | 縦棒・1系列 | 月ごとの水準比較 |

残高のグラフには安全ラインを破線で重ねる。そのためだけにK列へ
各行同じ値を置いている（グラフは系列として同じ長さの列を要求するため）。
利益率はL列。

金額と率は単位が違うので同じグラフに混ぜない（軸を2本持つグラフは作らない）。

`sheet.clear()` ではグラフは消えないので、作り直す前に
`getCharts()` で取得して `removeChart()` する。これをしないと
実行のたびにグラフが増える。

## 月内の資金繰り

出金が月の前半、入金が後半にあると、月末残高が黒字でも途中で一度
ショートすることがある。月単位の表では見えないので日別の表を分けてある。

- 月初残高は資金繰り予測の同じ月から引く
- 入金は「入金日」と「売上に対する割合」で置く。固定額を入れればそちらが優先
- 出金は支払い予定タブの支払日でSUMIF。納税は31日に置く
- 月末は31日として扱う（実際の末日が28〜30日でも、月内の前後関係は変わらない）
- 一番細る日とその金額を下にまとめる

## 作り直しても消えないもの

退避は `resetSheet_` を呼ぶ**前**に行う。あとで読むと空のシートを
読むことになり、入力が全部既定値に戻る。

- 設定タブの入力値（keyで突き合わせて引き継ぐ）
- 支払い予定の支払日・方法・メモ（項目名で突き合わせて引き継ぐ）
- 月内の資金繰りの入金予定（行の位置で引き継ぐ）

PLに項目を足したときは、メニューの「支払い予定の項目をPLから読み直す」で追従する。

## タブを作る順番

参照先のタブが存在しない状態で数式を書くと、Googleスプレッドシートは
その参照を `#REF!` に固定する。あとからタブを作っても直らない。

そのため `setupManagementSheets` は、まず全タブの器を作ってから、
参照される側の順（設定 → 資金繰り予測 → ダッシュボード → 納税カレンダー →
支払い予定）で中身を書く。

## 結合の解除はシート全体を指定する

`getDataRange().breakApart()` では、結合範囲がデータ範囲より外に
はみ出していると「結合範囲のすべてのセルを選択する必要があります」で落ちる。
結合セルの値は左上にしか入らないため、データ範囲が結合の右端まで
届かないことがある。

シート全体（`getRange(1, 1, getMaxRows(), getMaxColumns())`）を
指定して解除する。

## 結合と固定は両立しない

結合されたセルが行や列の固定の境目をまたぐと、Googleスプレッドシートは
`setFrozenColumns` / `setFrozenRows` を弾く。

資金繰り予測は1列目（月）を固定するので、見出しの帯は
**2列目から結合**している。色は行全体に敷くため見た目は1本の帯のまま。
表の下の注記も同じ理由で2列目から。

## 検証

`SpreadsheetApp` のモック（セルの値を実際に保持する）で通しの実行を確認している。
モックは数式を書き込むたびに `'シート名'!` の参照先が既に存在するかを検査するので、
`#REF!` になる書き順を実行前に見つけられる。
また Sheet と Range のメソッドを実際のAPIと同じに揃えてあるので、
`sheet.clearDataValidations()` のような存在しない呼び出しはモックの時点で落ちる
（`clearDataValidations` は Range 側にしか無い）。

結合も記録していて、固定の境目をまたぐ結合や、結合を覆いきれない範囲での
解除は、実物と同じように落ちる。
2回実行してもタブが増えないことも見ている。
